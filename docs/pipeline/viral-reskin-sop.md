> **调研日期**：2026-10-01

> **配套内部文档**：

## 0. 流程总览

"爆款复刻" = **选爆款 → 拉片拆解 → 角色替换 → 资产冻结 → 分镜重走（灰样） → 生成 → 交付**，共 7 个节点、6 道门禁。
与原创流程的最大区别：**分镜结构是"借"来的，创意投入集中在"换皮"（角色/场景/文案改写）上**；成本投入集中在生成环节之前用灰样验证节奏，生成环节按 IR 只换 `characters` 引用、分镜结构复用。

## 1. 选爆款标准：可复制性评分

### 1.1 评分表（5 维，每维 0–2 分，总分 10 分，**≥7 分才值得复刻**）

| # | 维度 | 2 分 | 1 分 | 0 分 | 为什么重要 |
|---|------|------|------|------|-----------|
| D1 | **无真人依赖** | 纯动画/纯 AI 生成，无真人出镜、无真人表情演技 | 有真人出镜但声音/配音是核心，真人可被替换 | 真人表情、演技、颜值是爆款核心 | 真人爆款复刻必然失真；AI 动画爆款的"演技"就是 prompt，可完整复刻 |
| D2 | **模板化结构** | 开头钩子 + 中段 N 个节拍 + 结尾 CTA/反转，结构清晰可数 | 有结构但节拍模糊 | 全靠灵感/临场发挥，无固定结构 | 结构越模板化，拉片拆解越精确，IR 重走越省力 |
| D3 | **时长适配** | 15–60 秒（短视频黄金时长） | 60–90 秒 | <15 秒（信息量不够）或 >90 秒（完播压力大） | 复刻目标是完播率，时长直接决定完播难度 |
| D4 | **数据信号** | 播放量 ≥ 作者粉丝量 5 倍（破圈），或点赞率 >5%、评论率 >1% | 数据好但未明显破圈 | 数据平平、靠投流撑起 | 破圈=内容本身有传播力，不是粉丝基本盘；点赞/评论率阈值参考短视频运营经验 `[待验证/传闻]` |
| D5 | **复制信号** | 评论区出现"求教程/求同款/这个模板在哪"类评论，或已有多个模仿版本 | 有人问"怎么做的" | 无人讨论制作方法 | "求同款"=观众已验证可复制性，这是最强的复刻绿灯 |

**计分规则**：
- 逐项打分并记录打分依据（链接/截图存档到项目目录）。
- **D1 = 0 直接否决**（真人演技型爆款不在本工作流范围内），不进入总分比较。
- 总分 ≥7 分 → 进入拉片；5–6 分 → 观望（可等出模仿版再评估）；≤4 分 → 放弃。

### 1.2 数据信号怎么看（无后台权限时的代理指标） `[部分已验证]`

- **完播率**：他人账号的完播率看不到。用代理信号代替：短视频运营经验中，完播率 <30% 通常要优化前 3 秒 `[待验证/传闻，来源：360doc 短视频制作文章]`。复刻时我们能控制的是**前 3 秒钩子强度**和**镜头平均时长**（爆款多为 1.5–3 秒一切，参考开源技能 SECOND-KNOWLEDGE-BRAIN 的经验值 `[已验证]`）。
- **互动率**：公开可见。点赞率 = 点赞/播放，评论率 = 评论/播放；经验阈值点赞率 <3%、评论率 <1% 视为偏弱 `[待验证/传闻]`。
- **破圈度**：播放量 / 作者粉丝数。开源分析工具 `local-video-content-analyzer` 把 `views / author_followers` 定义为 `viral_score`，阈值默认 5.0 `[已验证，来源：GitHub gaojesse999/ai-scripts]`。本 SOP 采用同一口径：**viral_score ≥ 5 即视为破圈爆款**。
- **复制信号**：评论区关键词"求教程/求同款/模板/链接"出现 ≥3 条，或站内搜索到 ≥2 个明显模仿版本 → D5 给 2 分。

## 2. 拉片拆解模板

### 2.1 使用说明

1. **先看三遍**：第一遍看整体情绪曲线，第二遍按暂停逐镜记录，第三遍核对台词/音效/字幕。
2. **镜头切分用实测不用目测**：有条件时用 `ffmpeg` 场景检测取切点（精确到 0.01 秒）；纯人工时以"画面内容突变/转场"为切点并标注 `[人工估时]`。开源 `video-shots` 技能强调"About 3 seconds 和 2.97 秒决定了表格能否用于剪辑" `[已验证，来源：GitHub mihaiserban/reelbench-skills]`。
3. **证据分级**：每格信息标注来源 —— `实测`（工具测得）/ `目测`（人工读取）/ `推断`（合理推测，如未标明的运镜意图）。借鉴 `Bailing-viral-video-remake-3.0` 的 `analysis_contract.md` 的证据规则：推断的文案不得当作原文转录 `[已验证]`。
4. **只记机制笔记，不抄原文**：台词栏记录"句式+功能"（如"反问句，抛痛点"），**禁止逐字抄录原台词**进拆解表（合规要求，见 §5）。需要原文比对时单独存档、不进入生产目录。
5. 输出文件：`projects/<项目>/pull-sheet.md`，拉片完成即进入门禁 G2。

### 2.3 填写要点

- **"画面动作"写"动词+对象"**，一个镜头只写一个核心动作（对应 `sop/gates.md` Phase 4 "每个镜头只有一个动作"的门禁要求）。
- **"情绪节拍/笑点"列是复刻的灵魂**：记录的是"观众此刻的感受"，换皮时这一列**不许变**，变的是前面的画面动作列。
- **"可复刻的结构公式"**：拉片的最终产出，一句话抽象，下一阶段（§3）照着它填新角色。

## 3. 角色替换方法论：原角色特征提取 → 新角色设计 → 资产锁定 → IR 重走分镜

> 全程以 **柴犬 → 甲虫** 为例。假设原爆款：一条贱萌柴犬的 30 秒整活短片（扑空抱枕→装无辜→反转得逞）。

### 3.1 第一步：原角色特征提取（画"特征-功能"对照表）

不要提取"柴犬长什么样"，要提取**每个特征在笑点机制里的功能**。功能可迁移，形态可换。

| 原角色特征 | 在爆款机制中的功能 | 功能标签 |
|-----------|-------------------|---------|
| 四肢奔跑、扑跳 | 制造"扑空"的物理笑点（动作幅度大） | `PHYSICAL-GAG` |
| 摇尾巴 | 快乐/得意的情绪信号灯 | `EMOTION-SIGNAL: happy` |
| 歪头杀 | "装无辜"的核心表情 | `EMOTION-SIGNAL: innocent` |
| 贱萌性格（故意使坏、耍赖） | 观众对"小坏蛋得逞"的代入感 | `PERSONALITY: mischievous` |
| 圆滚体型 | Q 版亲和力，翻车时更滑稽 | `SILHOUETTE: round` |

### 3.2 第二步：新角色设计（功能映射表：柴犬 → 甲虫）

映射原则：**功能一一对应，形态彻底换掉**（形态越不像，IP 风险越低，见 §5）。

| 功能标签 | 柴犬形态（原） | 甲虫形态（新） | 映射逻辑 |
|---------|---------------|---------------|---------|
| `PHYSICAL-GAG` | 四肢奔跑扑向抱枕 | **六足爬行冲刺**，扑向树叶/面包屑 | 四肢动作 → 六足动作：保持"冲刺+扑空"的节拍，足数变化反而增加新奇感 |
| `EMOTION-SIGNAL: happy` | 摇尾巴 | **触角快速摆动** + 鞘翅轻微开合 | 尾巴是"情绪外显器官"→ 甲虫的触角/鞘翅承担同一功能 |
| `EMOTION-SIGNAL: innocent` | 歪头杀 | **整个身体侧倾 15°，触角下垂** | 狗歪头是"头部不对称卖萌"→ 甲虫没有脖子，用全身侧倾+触角下垂实现同一"无辜感" |
| `PERSONALITY: mischievous`（贱萌） | 故意使坏、耍赖 | **憨莽**：力大无脑、横冲直撞、闯祸后一脸无辜 | 性格迁移不是平移是"转译"：保留"闯祸-无辜"的情绪节拍，把"贱"（主动使坏）转成"莽"（被动闯祸），笑点机制不变、人物弧光更新鲜 |
| `SILHOUETTE: round` | 圆滚体型 | **圆滚鞘翅身体，Q 版头大身小** | 剪影功能（亲和+滑稽）保留，物种彻底换掉 |

**标志性动作"神韵保留、形态替换"示例**（原片 SH02 扑空抱枕）：
- 神韵 = 节拍：`蓄力（0.5s 静止）→ 冲刺（0.8s）→ 扑空（定格 0.3s）→ 无辜脸（1s）`
- 新形态 = 甲虫六足刨地蓄力 → 冲向面包屑 → 一头撞翻 → 触角下垂装无辜
- **节拍时长照抄，动作内容全换** —— 这就是"复刻套路不抄表达"。

### 3.3 第三步：沉淀为角色卡 + 连续性锁

按 `prompts/templates/character-card.template.md` 为新角色建卡（`characters/CHAR_B001.md`），关键在 `continuity_locks`：**每条锁一句话、中英双语、生成 prompt 里逐字复制**。

```yaml
character_id: CHAR_B001
name: "铁头"
role: protagonist
appearance:
  body: "圆滚滚的黑色甲虫身体，Q版头大身小，约茶杯大小"
outfit:
  default: "无衣物，鞘翅上有两道金色条纹"
art_style: "3D 卡通渲染，皮克斯风格，干净描边"
color_palette: ["#1a1a1a", "#f5c518", "#8b5a2b"]
seed: 42001
continuity_locks:
  - id: LOCK-BODY
    zh: "圆滚滚的黑色甲虫身体，六条短腿，鞘翅上有两道金色条纹"
    en: "round black beetle body, six short legs, two golden stripes on elytra"
  - id: LOCK-ANTENNA
    zh: "头顶两根弯曲触角，开心时摆动，装无辜时下垂"
    en: "two curved antennae on head, wiggling when happy, drooping when playing innocent"
  - id: LOCK-SCALE
    zh: "体型约等于一只茶杯，Q版比例头大身小"
    en: "teacup-sized, chibi proportions with big head and small body"
version: v1.0
frozen_by: ""
frozen_at: ""
```

> 注：`frozen_by` / `frozen_at` 在门禁 G3（资产冻结）由用户确认后填写，冻结后只读。

### 3.4 第四步：用 IR 重走分镜（timeline.json 只换引用，结构复用）

对照 `docs/pipeline/ir-spec.md` 的双层结构：

**层 1 `assets.json`** —— 新增甲虫角色，旧角色保留（不断历史）：
```json
{
  "characters": {
    "CHAR_001": { "card": "characters/CHAR_001.md", "locks": ["LOCK-FACE", "LOCK-OUTFIT"] },
    "CHAR_B001": { "card": "characters/CHAR_B001.md", "locks": ["LOCK-BODY", "LOCK-ANTENNA", "LOCK-SCALE"] }
  }
}
```

**层 2 `timeline.json`** —— shot 结构（`shot_id`、`camera`、词锚定 `lines/words` 节奏骨架）**原样复用**，只做两处替换：
1. `"characters": ["CHAR_001"]` → `"characters": ["CHAR_B001"]`；
2. `lines[].text` 按"句式保留、措辞改写"重写（不抄原台词，见 §5），`words` 词级时间戳由新 TTS 实测重打（锚定在词上，改词自动重排时间轴）。

```json
{
  "shots": [
    {
      "shot_id": "RSK01_SH02",
      "characters": ["CHAR_B001"],
      "scene": "SCENE_B001",
      "camera": { "shot_size": "medium", "movement": "dolly in" },
      "lines": [
        { "text": "看我的无敌冲刺！",
          "words": [ { "w": "看我", "t0": 0.0, "t1": 0.4 }, { "w": "的无敌冲刺！", "t0": 0.4, "t1": 1.2 } ] }
      ],
      "takes": 3
    }
  ]
}
```

**机检衔接**：`gate_check.py`（`sop/gates.md` Phase 4 门禁）逐镜检查 prompt 是否包含该角色**全部**连续性锁短语 —— 换皮后机检对象自动从 `LOCK-FACE/LOCK-OUTFIT` 切换为 `LOCK-BODY/LOCK-ANTENNA/LOCK-SCALE`，无需改脚本。

## 4. 每阶段门禁 Checklist

> 复用 `sop/gates.md` 风格：`[自动]` = 脚本可校验，`[人工]` = 必须用户明确确认（"继续"/空回复/表情不算确认，见 §6.2 确认语义）。

### G1 选爆款确认 → 拉片
- [ ] [自动] `projects/<项目>/candidate.md` 存在（含原片链接、数据截图、viral_score 计算）
- [ ] [自动] 可复制性评分表（§1.1）已填，总分 ≥7，且 D1 ≠ 0
- [ ] [人工] 用户确认"这个爆款值得复刻"（明确肯定该**具体**视频，不是"找个爆款吧"）

### G2 拉片完成 → 角色替换
- [ ] [自动] `pull-sheet.md` 存在，逐镜表无空行（镜号连续、时长总和 = 全片时长 ±0.5s）
- [ ] [自动] "可复刻的结构公式"已填（一句话抽象模板）
- [ ] [自动] 风险初筛（§2.2 第 3 节）四项全勾选
- [ ] [人工] 用户确认"结构公式抓住了爆款的魂"（只认机制，不认具体画面）

### G3 新角色资产冻结 → 分镜重走
- [ ] [自动] 角色卡 `characters/CHAR_Bxxx.md` 完整（含定稿图、seed、voiceId、全部 LOCK-* 中英双语）
- [ ] [自动] 功能映射表（§3.2）已归档：每个原功能标签都有新形态对应
- [ ] [人工] 用户已点选确认新角色定稿图（三视图）
- [ ] [人工] 用户亲口确认"角色卡冻结"（冻结后只读，`frozen_by/frozen_at` 落盘）

### G4 分镜重走（灰样） → 生成
- [ ] [自动] `timeline.json` 已生成：shot 结构复用原拉片表，`characters` 引用已切换为新角色 ID（ID 存在性校验，引用不存在则拒绝入队 —— 引自 `ir-spec.md` "fail loud"）
- [ ] [自动] 每个镜头的 prompt 包含新角色全部连续性锁短语（机检）
- [ ] [自动] 台词已改写：与原片台词逐字重复率 <30%（脚本自检，阈值可调）
- [ ] [人工] **灰样已过**：零成本预演（镜头顺序 + 对白时间轴 + 关键静帧由角色定稿图拼成），用户确认"节奏成立、笑点节拍对"

### G5 生成 → 交付
- [ ] [自动] 每个镜头 ≥1 个可用 take，命名规范
- [ ] [自动] 三处质检点记录完整（静帧/抽帧/拼接）
- [ ] [人工] 用户已终审所有镜头（"通过/换一个"二选一完成）

### G6 交付
- [ ] [自动] AI 标识角标已加
- [ ] [自动] BGM 来源为无版权音乐或平台曲库（附授权/来源记录）
- [ ] [人工] 平台合规已确认（无搬运判定风险、无侵权投诉隐患）
- [ ] [自动] `runs/<时间>/` 记录完整（模型/prompt/seed 可复现）
- [ ] [人工] 用户验收通过

## 5. 合规红线专节：复刻爆款的 IP 风险

> **本节为一般性指引，非法律意见。** 具体案件的侵权判定以执业律师意见和法院判决为准；平台规则（如抖音/快手对"搬运"的判定）另有一套社区标准，同样要遵守。

### 5.1 法律原理（一句话版）

著作权保护的是**独创性表达**，不保护**思想、创意、套路本身** —— 即"思想/表达二分法" `[已验证，来源：HansPub《"智能剪辑"短视频的可版权性》；Wikipedia"有版权资料的改写"]`。美国法上的测试是"接触 + 实质性相似"，且相似必须落在**表达层面**而非思想层面 `[已验证，来源：thefashionlaw.com]`。

落到本工作流：**"套路/结构/笑点类型"是思想层，可学；"具体角色形象、具体台词、具体音乐"是表达层，不可搬。**

### 5.2 "安全复刻 vs 侵权"判定清单

| # | 检查项 | ✅ 安全复刻 | ❌ 侵权/高风险 |
|---|--------|------------|---------------|
| 1 | 剧情结构 | 复刻"钩子→翻车→装无辜→反转"的节拍公式 | 照搬原片独有的情节串联顺序（多处巧合到"像"） |
| 2 | 角色形象 | 全新设计（柴犬→甲虫），功能映射、形态彻底换掉 | 直接使用/微调知名 IP 角色形象（如某动漫主角换色） |
| 3 | 台词文案 | 只借**句式和功能**（反问抛钩子），措辞全部重写 | 逐字/近逐字复制原片独创金句、口头禅 |
| 4 | 音乐音效 | 无版权音乐、平台曲库、或自制音效 | 直接扒原片 BGM（商业版权音乐） |
| 5 | 笑点类型 | 复刻"反差/打脸"这类**类型** | 复刻原片**独创的具体包袱设计**（同一梗、同一反转点、同一视觉包袱） |
| 6 | 视觉设计 | 分镜景别/运镜可借鉴（镜头语言属通用技法） | 复制原片具有独创性的美术风格+角色+场景组合（整体观感"就是它"） |
| 7 | 合理使用抗辩 | 不依赖：我们做的是"换皮新表达"，不是"引用原片" | 指望"只抄一点点/注明出处"免责 —— 注明出处**不**构成不侵权 `[已验证，思想表达二分法相关文献均强调此点]` |

**经验法则**（来自短剧仿写社区的三层拆解法 `[已验证，来源：GitHub lixiaoxiao9888-create/short-drama-factory · mechanism-imitation.md]`）：
- 机制层（情绪流、节奏公式）→ 自由使用；
- 结构层（人物功能位、反转类型）→ 可借用，但必须换皮换参；
- 表达层（具体台词、角色名、专有设定、独特桥段顺序）→ 不可搬。
- 附加操作规程：拆解笔记**禁止粘贴原台词原文**；六档/多节拍中至少 2 处须为本项目原创，否则回炉。

### 5.3 音乐专项

- BGM **必须**来自：无版权音乐库（如 YouTube 音频库类）或发布平台的官方曲库（剪映/抖音曲库等），保留来源记录备查。
- 通用音效（"噗""咚"类）通常无风险；有辨识度的影视原声采样一律不用。
- 用户自带音乐 → 要求用户书面确认其拥有授权，记录进 `runs/`。

### 5.4 平台"搬运"判定风险（非版权、但同样致命） `[待验证/传闻]`

即使法律上不构成侵权，平台也可能将"与爆款过像"的视频判为低质/搬运而限流。社区经验：同一赛道已有多个模仿版时，平台对"又一个换皮版"的推荐会打折扣。因此 D5（复制信号）是双刃剑：**有模仿版证明可复制，但模仿版太多则红利耗尽** —— G1 人工确认时需一并判断"窗口期是否还在"。

## 6. 成本控制

### 6.1 灰样先行（零成本环节清单）

| 环节 | 灰样做法 | 成本 |
|------|---------|------|
| G1 选爆款 | 只看公开数据 + 评论区，不下载原片（必要时只存档链接） | 0 |
| G2 拉片 | 人工/脚本拆解表，ffmpeg 场景检测本地跑 | 0（本地算力） |
| G3 角色设计 | 先出文字版功能映射表 + 免费草图确认方向，**定稿图生成前先经用户看文字方案** | 0（文字阶段） |
| G4 分镜重走 | **灰样 = 镜头顺序 + 对白时间轴 + 角色定稿静帧拼成的 slideshow**，用户确认节奏成立后才进入视频生成 | 0 |
| G4→G5 过渡 | 先生成 **1 个最难的镜头**（动作最复杂的）验证角色一致性，通过再批量 | 首镜试错成本，非整批 |

原则：**任何按整批计费的调用，前面必须有一个零成本/单样本验证门。**

### 6.2 需要用户明确确认的节点（确认语义）

以下节点缺一不可，且适用统一确认语义 ——

> **确认语义**：用户针对**本次批次的具体内容**作出**明确肯定**（如"这个甲虫定稿图可以了""灰样节奏没问题，去生成吧"）。"继续""嗯""👍"/空回复/表情**不算**确认。agent 在收到模糊回复时必须追问一次，追问后仍无明确肯定则**停在门禁前**，不得自行放行。

| 门禁 | 确认对象（必须具体） |
|------|---------------------|
| G1 | 具体哪一条爆款（链接）值得复刻 |
| G2 | 拉片总结的"结构公式"是否抓住了爆款机制 |
| G3 | 新角色三视图定稿 + 角色卡冻结 |
| G4 | 灰样（节奏/笑点节拍）成立 |
| G5 | 每个镜头的"通过/换一个"终审 |
| G6 | 最终成片验收通过 |

### 6.3 花钱门（调用付费接口前先报价）

引自 `ir-spec.md` 门控：**花钱门 —— 调用付费接口前先报价 + 显式确认，确认标志永不静默。**

执行细则：
1. **报价先行**：G4 灰样通过后、G5 批量生成前，agent 必须给出书面报价单：镜头数 × 单镜头预估成本 × takes 数 = 本次批次预估总成本，并注明"重生成/追加 takes 另计"。
2. **按批确认**：用户对**该报价单**明确确认后，才提交第一批任务；中途追加 takes/重跑 → 重新报价、重新确认。
3. **三账本对账**：每次运行写 `runs/<timestamp>/` 三账本（`task_state.json` / `provider_checkpoint.json` / `artifacts.json`），`submitted = 很可能已计费`，断点续跑不重复花钱。
4. **熔断**：单批次失败率 >50%（`failed_stage` 汇总）时自动暂停，转人工决策是否继续烧钱。
