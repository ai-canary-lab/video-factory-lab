# SOP 前期：创意 → 剧本 → 角色 → 场景 → 分镜

> 前期是质量的生死线。AI 在这里只做**执行**，不做**创意决策**。

## Phase 0 立项

- **用户动作**：一句话说出创意（"想做个什么样的视频"）。
- **Agent 动作**：问 5–7 个引导式选择题（题材、时长、观众、风格、产品线归属），
  整理成 `projects/<项目>/brief.md`。
- **产出**：一页纸立项书。

## Phase 1 剧本

两种协作模式，agent 按剧本长度自动选择：

- **A. 共创模式**（短剧本，< 2000 字）：agent 起草 → 用户在对话里改 → 定稿。
  agent 一次只抛一版，修改意见一次只收一轮，避免来回拉扯。
- **B. 外部工具模式**（长剧本/用户想自己写）：agent 推荐成熟的写作工具
  （在线文档如 Notion/Google Docs，或专业剧本软件），用户在外面写好后
  把文档贴回或上传，agent 负责结构化、切分时长、冻结为 `script-v1.0.md`。
  选择逻辑：用户说"太长了/想自己写" → 切 B 模式，不要硬在聊天里写万字文档。

- **产出**：`projects/<项目>/script-v1.0.md`（对白/旁白精确到秒）。
- **门禁**：剧本冻结打 tag 后，任何改动都要升版本号并评估对分镜的影响。

## Phase 2/3 角色设计 & 场景设计

高效协作模式（不要让用户逐张精修）：

1. 用户用文字描述角色/场景，或丢 1–2 张参考图（"大概长这样"）。
2. agent 生成**九宫格候选**（同一描述 9 种变体，一次呈现）。
3. 用户**点选**最接近的一张（只做选择题）。
4. agent 以选中图为基准生成三视图（正/侧/背），用户确认后**冻结**为
   角色卡 / 场景卡（`prompts/templates/*.template.md`）。
5. 冻结后全片复用，任何人不得改 —— 要改就升版本并重跑受影响镜头。

- **产出**：`projects/<项目>/characters/*.md` + 定稿立绘，
  `projects/<项目>/scenes/*.md` + 定稿场景图。

## Phase 4 分镜

1. agent 按冻结剧本拆分镜表（`shots.yaml`，见 `prompts/templates/shot-prompt.template.md`），
   每个镜头只有一个动作。
2. 用户逐镜头确认**动作一句话**（"他推开门走进去"这种粒度）。
3. agent 组装完整 prompt（角色卡块 + 场景卡块 + 动作 + 运镜），冻结分镜表。

- **产出**：`projects/<项目>/shots.yaml`（冻结）。
- **注意**：分镜静帧可以先出（生图），用户先审静帧再转视频 ——
  这是 2026 年社区验证最省钱的一致性手段（storyboard-first）。
